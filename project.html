Goal: Minimize Damage

Defining an "Incident"

An Incident is a violation of security policies that threatens data confidentiality, integrity, or availability.

Not an Incident (Event)

Server Failure (Old Hardware)

A hard drive dying is an operational issue. It's annoying, but it's not an attack. We fix it and move on.

Security Incident

Server Failure (DDoS Attack)

A hacker overwhelming the server to take it offline is a crime. This requires a forensic investigation.

Analogy: The Fire Dept
IT Support are the carpenters fixing a broken door. Incident Responders are the Firefighters rushing in when the building is burning.

Why Use a Framework?

In a crisis, panic is the enemy. We follow strict government (NIST) or industry (SANS) checklists so we don't forget steps.

NIST SP 800-61 (The Government Standard)
  1. Preparation Getting ready before it happens.
  2. Detection & Analysis Figuring out what is happening.
  3. Containment, Eradication, & Recovery Stopping it and fixing it.
  4. Post-Incident Activity Learning from mistakes.

The Golden Rule

NIST groups the middle steps, but in practice, we must separate them:

Containment Eradication Recovery

You cannot recover (restart) until you eradicate (clean). If you restart a dirty system, you get reinfected immediately.

Phase 2b: Analysis & Triage

Not every alert is real. We must "Triage" to separate real threats from noise.

False Positive

Looks bad, but is harmless.

"Alert: High outbound traffic from Finance Server."

Reality: Bob in accounting is uploading a large backup to the cloud.
Action: Close Ticket.

True Positive

Actual malicious activity.

"Alert: PowerShell script executed by 'Admin' at 3 AM."

Reality: The Admin is on vacation. This is a hacker using stolen credentials.
Action: DECLARE INCIDENT.

Phase 3: Containment (Stop the Bleeding)

Strategy: Isolation

  • VLAN Quarantine We move the infected computer to a digital "jail" network. It can't talk to other computers, but we can still study it remotely.
DO NOT POWER OFF!
Turning off the computer destroys evidence in the RAM (Memory). Just unplug the internet cable.

Strategy: Segmentation

If the attackers are moving through the network, we cut the bridges.

  • Lateral Movement Defense Block connections between departments. (e.g., HR computers shouldn't be talking to Engineering servers).

Phase 4 & 5: The Cleanup

Eradication

You cannot just "delete" the virus file. Hackers hide "backdoors" to get back in later.

The Only Safe Way:
Wipe the drive & Re-install Windows

Recovery

We restore data from backups. But we must be careful—what if the backup is also infected?

The Strategy:
Restore from a date BEFORE the attack.

Digital Forensics: Volatility

Digital evidence is fragile. Some of it disappears the moment you pull the plug. We follow the Order of Volatility.

  1. 1. CPU & Cache(Gone in nanoseconds)
  2. 2. RAM (Memory)(Gone when power is cut)
  3. 3. Hard Drive / HDD(Persistent - Safe to unplug)

Analogy: The Melting Ice Cream

RAM is like ice cream. If the power goes out (freezer stops), it melts immediately and the evidence is gone forever. The Hard Drive is like a frozen steak—it will stay frozen for a long time.

Always collect the ice cream (RAM) first!

Digital Forensics: Chain of Custody

If we want to prosecute the hacker, the evidence must stand up in court. We need proof we didn't tamper with it.

1. The Write Blocker

A physical device we plug the hard drive into. It ensures we only READ data, never WRITE to it.

Skill: Bit-by-Bit Imaging

We never work on the original drive. We create a perfect "Bit-Stream" clone and work on the copy.

2. Hashing (Digital Fingerprint)

We run a math formula (MD5 or SHA256) on the hard drive contents. It gives us a unique string of characters.

Hash Before: 5e884898da28047151d0e56f8dc62927
Hash After:  5e884898da28047151d0e56f8dc62927

If even one single bit changes, the hash changes completely. This proves the evidence is authentic.

Scenario: Ransomware Attack

The Situation

Tuesday, 2:00 PM: An HR employee calls the Help Desk. Their screen is locked with a giant red skull. A message demands $50,000 in Bitcoin to unlock their files.

POP QUIZ: What is your first move?
  • A) Pull the power plug immediately.
  • B) Unplug the Network Cable (Ethernet/WiFi).
  • C) Pay the ransom.

"Your files are encrypted. Payment is required."

Scenario: Why B is Correct

Reason 1: Stop Lateral Movement

Ransomware is designed to "worm" its way to other computers. If you unplug the network cable, the virus is trapped on that one machine. You save the rest of the company.

Why A (Power Off) is Wrong

Sometimes, the encryption key (the password to unlock your files) is temporarily stored in the RAM. If you pull the plug, the RAM is wiped, and the key is gone forever. You might have just destroyed the only way to get your files back for free.

Phase 6: Post-Incident Activity

The battle is over. Now we must learn from it so it doesn't happen again.

The "Hot Wash" Meeting

A meeting held immediately after the incident while memories are fresh.

  • What exactly happened?
  • What did we do right?
  • What did we do wrong?
  • How can we detect this faster next time?

The Final Report

A formal document given to management. It justifies the budget for new security tools.

"Never let a good crisis go to waste."
